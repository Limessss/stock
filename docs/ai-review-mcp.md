# AI复盘：外部 Agent → MCP → 时间轴

项目侧负责提供本地数据、保存报告和展示。Codex、Claude Code 等外部 Agent 负责分析；本功能不调用项目「大模型设置」中的模型。

## 日常使用

1. 启动项目后端和前端，进入侧栏的 **AI复盘**。
2. 选择复盘日期（默认本地情绪数据最近完成的日期），点击 **复制AI复盘指令**。
3. 粘贴到本机 Codex / Claude Code 会话。指令包含 MCP 配置、读取步骤、复盘框架与提交格式。
4. Agent 调用 `submit_ai_review` 提交完整 Markdown，再通过 `get_ai_review` 核验回执。本页每 15 秒检查新报告，也可以手动刷新。

首次使用需要在 Agent 客户端加载 MCP。提示词不能保证客户端能在当前会话动态增加工具；如果客户端要求重载，请按它的提示重新加载 MCP 或开启新会话。页面 **MCP 接入** 提供按当前项目路径生成的可复制配置。

报告按 **复盘日期 → 提交时间 → ID** 排序，默认最新在前，可切换正序。同一天多个 Agent、同一 Agent 的多次复盘均追加保存，支持按日期区间、Agent、标题/正文筛选。报告详情支持 Markdown 表格、列表、引用、复制和下载；不执行原始 HTML。文末“数据与依据”及归档信息默认折叠，点击可查完整名单和来源；复制、下载及 MCP 读取始终保留完整报告。

## MCP 接入

在项目根目录运行 `uv sync` 安装依赖。后端启动示例：

```powershell
.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

MCP 采用官方 Python SDK 的 stdio 传输，客户端启动 `backend/mcp_server.py`。它通过 HTTP 访问项目后端，不需要单独启动一个 MCP 网络端口。

从 **AI复盘 → MCP 接入** 复制本机配置，合并到对应文件，不要覆盖原有配置：

- Codex：`~/.codex/config.toml` 中的 `[mcp_servers.stockmodel]` 和 `[mcp_servers.stockmodel.env]`。
- Claude Code：项目 `.mcp.json` 中的 `mcpServers.stockmodel`。

配置中的 Python 可执行文件和脚本均为绝对路径，允许从其他工作目录启动。`STOCKMODEL_API_URL` 必须包含 API 前缀，默认 `http://127.0.0.1:8000/api`；后端端口不同则修改该值。`PYTHONUTF8=1` 确保 Windows 中文传输。这里提供的是同一台电脑上的本地连接，其他电脑或云端 Agent 不能直接使用这些路径。

配置格式参考：[Codex MCP 官方文档](https://developers.openai.com/codex/mcp)、[Claude Code MCP 官方文档](https://code.claude.com/docs/en/mcp)。服务实现使用 [MCP 官方 Python SDK](https://github.com/modelcontextprotocol/python-sdk)。

## 提供的工具

| 工具 | 用途 |
| --- | --- |
| `get_review_context(trade_date, lookback_days=30)` | 默认回看 30 日，必要时扩至 60/120 日；返回行情、强弱板块、题材与梯队摘要和此前报告，先看 window_coverage、availability 和 caveats |
| `get_review_day(trade_date)` | 指定日完整已缓存排名、梯队、涨停原因、题材关系、跌停名单及最多 100 只新高样本 |
| `get_stock_history(code, end_date, bars=60, adjust="none")` | 截至指定日期的本地个股/指数日线及指标，返回实际数据截止日 |
| `list_ai_reviews(start_date?, end_date?, agent_name?, q?, order?, page?, page_size?)` | 分页查询报告摘要，历史分析应指定 end_date |
| `get_ai_review(report_id)` | 查看完整报告或核验提交 |
| `submit_ai_review(report)` | 追加保存报告，返回 ID、是否新建与页面路径 |

另提供 MCP prompt `daily_review(trade_date)`，与页面复制的指令采用同一模板。

## 复盘依据与版本

AI 复盘直接引用用户维护的原文件：

`C:/Users/66470/Desktop/Memo/Memo/情绪周期/完整情绪周期操作手册.md`

每次点击 **复制AI复盘指令**、展开预览，或调用 MCP prompt `daily_review`，都会重新向后端请求指令，由后端读取原文件全文。正文与方法版本来自同一次读取；版本为 SHA-256 的前 12 位。保存手册后，下一次获取指令即生效，**无需重启前后端或 MCP**。已打开的预览不会监视文件变化，关闭后重新展开即可更新。

外部 Agent 接收到的指令包含当次手册全文，不必访问个人笔记路径；手册中的文献外链仅作出处，不要求后续 Agent 阅读原帖。项目不改写原文件。已复制的指令和已归档报告保留原版本，需要采用新方法时重新复制指令。历史导入文件 [ai-review-handbook.md](ai-review-handbook.md) 仅保留为旧快照，已不参与指令生成。

移动手册或换电脑时，可以在项目 `.env` 或后端环境变量中设置 `STOCKMODEL_AI_REVIEW_HANDBOOK_PATH` 指向新的完整路径，再重启后端加载路径配置。例如：

```dotenv
STOCKMODEL_AI_REVIEW_HANDBOOK_PATH=C:/Users/66470/Desktop/Memo/Memo/情绪周期/完整情绪周期操作手册.md
```

手册缺失、不可读、不是 UTF-8 或内容为空时，接口明确返回错误，页面不复制旧缓存，也不会退回历史快照。修复文件并保存后重试即可。

手册是用户指定的个人分析体系，其中阶段强弱是定性框架，不是经过统计验证的收益规律。实际复盘保留证据、推断和待验证条件的区别；正式报告直接呈现分析，仅在来源中记方法版本，不写学习经历或手册导读。

## 复盘流程

**主线与龙头 → 可参与赚钱效应 → 按当前手册定位阶段 → 阶段切换与次日纪律。**

完整复盘至少回看 **30 个交易日**，初次调用显式传入 `lookback_days=30`，必要时扩至 60 或 120 日，不能以 30 个自然日替代。API 与新启动的 MCP 工具默认值均为 30，上限为 120；较短窗口仅用于定向补充查询。已有 MCP 连接需重新加载后更新工具默认值和参数上限；重新复制的指令会显式传入 30，旧连接原有 30 日上限也能执行基础窗口。

`window_coverage` 返回请求天数、实际数据日期数、缺少天数、实际起止日期和各来源覆盖天数。指定日没有记录时，额外保留其缺失详情，不占用 30 日历史名额。窗口按本地行情/情绪记录确定，无法据此证明交易所日历完整；记录不足或某来源未覆盖时明确报告，不能声称已经具备完整的 30 日市场、题材与梯队数据。

首先比较核心候选，依据对应日期的梯队、题材关系、同窗口相对表现、分歧反馈、容量及助攻说明为什么选择该主线和龙头。最高板、单日涨幅或自身新高只能提供部分证据；空间参照、容量代表与主导核心分开。重要候选落选须有理由，不永久指定某只股票为总周期锚。主线未确认时列出竞争对象和确认条件。

### 阶段、角色及边界

阶段名称、定义、切换条件、角色关系与执行纪律均取自当次读取的手册。项目模板保留取证和报告要求，不再维护另一套固定阶段定义，避免手册更新后仍套用旧规则。旧报告与当前手册不一致时重新审视，并说明调整依据。

每个阶段判断都要说明满足了哪些条件、缺什么、最接近的另一种解释为何较弱；细分阶段需要额外证据。每条纪律都要核对适用范围，不能把附条件的规则扩大使用。角色判断分别说明启动归属、阶段作用和当前地位，以及支持关系改变的日期与反证。

先判断所研究主线，再检查市场整体负反馈的约束。市场、题材与个股可以不同；核心更替和阶段转换分别论证。回溯以解释当前主线的必要转折为限，不强行补齐证据不足的阶段，不无限堆砌强股历史。

### 参与质量与可获得的数据

阶段判断与具体买点分开。日线、成交额、完整梯队及固定群体的持续、扩散、分歧和修复，可以支持明确的阶段倾向；不能仅因缺少分时或用户交易记录，就将所有新方向一直限制在“启动/转一候选”。阶段关键条件若只有间接证据，说明这一处推断与最强反证，不修改手册定义，也不强行升级。

分时缺口限制的是具体分钟的成交、主动承接/带动、封单、真实退出和策略胜率等结论。开收盘和跨日变化能辅助判断参与质量，但不能冒充实际交易收益。当天新群体还没有后续反馈，属于持续性证据不足，不能笼统归因于没有分时。公共数据边界仅在附录说明一次；直接改变当前主判断的缺口才在正文就近说明。

固定历史核心、助攻、跟随和失败者检验连续反馈；不能每天换一批首板证明扩散，也不能用所有股票尚未回本否认身份变化。新分支应根据自身核心、容量与跟随者判断，旧方向修复不是其成立的一律前置条件。

仓位与动作仅按手册提供试错、确认后进攻、持仓管理、防守等条件性倾向。未取得用户风险预算和持仓时不指定仓位百分比，不虚构交易、盈亏或个性化持仓安排。

### 阶段切换记录与报告验收

正文先明确主线、龙头/竞争候选和阶段，再用日期串起“先前阶段 → 参与质量/修复/负反馈变化 → 当前阶段 → 反证与下一项验证”。原中位穿越与低位新起分支用来解释核心和题材的变化，须放回当前手册的阶段框架，不能替代阶段定义。

阶段记录随 Markdown 报告归档，包含主线与核心、前后阶段、参与质量变化、支持证据、反证或缺口、判断/确认日期、执行倾向、下一项确认或失效条件。区分当时可知、本次回溯和后来确认；引用承接的项目报告 ID，次日继续检验。固定名单及统计明细放必要附录，不用表格数量代替推演。

验收在 Agent 内部遵循当前手册的每日复盘清单，检查主线、角色及阶段的支持和反证、纪律范围、买点与收益表述的证据，并删除重复内容。检查清单不作为报告章节输出。

项目已有「龙头周期全景图」有序列表和保存区间，目前尚未暴露给这组 MCP 工具；可作为后续人工候选池接入，名称、排序及事后编辑不能直接证明当时的周期归属。

### 报告表达

正文目标约 **1500—2500 字，一般不超过 3000 字**，不含数据附录；重要切换可适当超出，不以删掉推理换取短篇幅。标题和摘要各司其职，正文不再复制标题、摘要或目录。摘要用于时间轴卡片，详情页直接呈现正文，避免开头重复一遍结论。

正文围绕四件事组织：今天最重要的变化；最重要的 2—3 条线索及其阶段切换；通常 3 项次日观察；旧预期的修正。用具体结论作小标题。赚钱效应、角色及阶段证据在对应线索中一次讲清，不再另开“参与质量”“阶段记录”“每日检查清单”等章节重复解释；其他方向按重要性简述。

每段 2—4 句，先说谁在什么日期变了，再说为什么影响判断。必要术语首次出现顺带解释。每项判断配 1—2 组关键数据及最强反证，次日计划直接写触发条件和调整，不重讲论据。正文保留统计基准、有效样本数及缺失；不能反复用“缺少分时”“候选”“不能确认”代替分析。

附录从文末单独的二级标题 `## 数据与依据` 开始，收纳固定名单、算法、来源、缺口、报告 ID 与方法版本。不要放完整日线流水账或搬入重复正文，不能把影响主判断的反证藏在附录。页面在 Markdown 解析后折叠该节，兼容旧标题“八、数据与依据”；代码块、引用中的同名标题和后续正式章节不折叠，引用链接仍在完整文档中解析。原始 Markdown 不变，复制、下载和 MCP 始终取得全文，不要求 Agent 输出 HTML。

中文标点与后续汉字紧邻的 Markdown 加粗，由 `remark-cjk-friendly` 的解析扩展处理，避免正文露出 `**`；代码和转义星号仍按原样显示，不改写入库内容。

这些写作要求由页面指令与 MCP prompt 共同提供。更新后重新获取指令即生效，原手册无需为此改写。

## 提交契约

`submit_ai_review` 接收一个 `report` 对象：

```json
{
  "report": {
    "trade_date": "2026-09-04",
    "agent_name": "Codex",
    "model": "",
    "title": "9月4日复盘：题材分歧与后续验证",
    "summary": "用几句话概括判断、证据和待验证条件。",
    "content_markdown": "## 市场环境\n\n这里是完整复盘正文。",
    "tags": ["题材分歧"],
    "linked_codes": ["SH600000"],
    "data_sources": ["get_review_day：2026-09-04，开盘啦缓存"],
    "submission_id": "为这份报告生成唯一UUID"
  }
}
```

必填项为 `trade_date`、`agent_name`、`title`、`content_markdown`。`model` 不确定时留空；其他列表字段和摘要可省略。可选 `data_cutoff` 必须含时区，例如 `2026-09-04T15:00:00+08:00`。正文上限 200,000 字符。

相同 Agent 与 `submission_id`、相同内容的重试返回原报告（HTTP 200，`created=false`）；相同 ID 但不同内容返回 409。新报告使用新 ID。未提供 ID 的每次成功调用都会追加报告。同一天和同一 Agent 都不是覆盖键。

数据库新增 `ai_review` 表，由现有启动建表流程自动创建；原有 `review_note` 不变。API 前缀为 `/api/ai-reviews`，其 `GET/POST` 与 `/overview`、`/instructions`、`/context`、`/context/day`、`/context/stocks/{code}`、`/{report_id}` 供页面及 MCP 服务共用。

## 数据边界

- 只读当前本地已同步数据，不自动同步开盘啦，也不发起交易。
- 优先读取开盘啦快照中的完整板块排名；没有快照时退回已有 `SentimentTheme`。`strength` 是来源强度分，不是资金净流入；`change_pct` 为百分数。
- 梯队 `board_count` 可能表示 N 天 M 板，需结合 `board_type` 和日线确认。题材归类不等于完整板块成分。
- 上下文和日线不会返回晚于指定日期的行情；不输出事后回填的 `is_major_first_board`。历史报告可能事后补写，上下文仅纳入截至复盘日已提交的此前报告。
- 当前数据库与复权因子可能修订，不能保证严格的历史时点可见性。日线默认未复权，除权日变化需要区别对待。
- `null` 与数据缺失不等于 0。缺少竞价、分时、封单变化、监管事件时，Agent 应明确列出，不补写盘中因果。
